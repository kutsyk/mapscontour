# Map exporter integration and implementation review

Reviewed source: `~/projects/vk.crafts/kutsyk.github.io-master/map-exporter/` (the five JavaScript modules, `index.html`, and the existing `MAX-EXPORTER-ANALYSIS.md`). The original project was read only and was not modified. This integration lives in `mapscontour-terrain`.

## What the original implementation does

`index.html` supplies Bootstrap controls and loads MapLibre and Bootstrap from CDNs. `js/main.js` owns DOM state, export progress, preview modal, downloads, retry settings and a five-entry in-memory Overpass cache. `js/search.js` searches Nominatim. `js/frame.js` adds two diagonal corner markers and a center marker over MapLibre. `js/overpass.js` translates selected layers and the bounding box into Overpass QL, requests OSM ways/relations with geometry, and tries three endpoints. `js/svg.js` projects coordinates to Web Mercator, scales them into a pixel canvas, classifies features, constructs SVG DOM nodes and serializes a layered SVG.

The layer taxonomy is useful: major/minor roads, road subtype colors, water areas and optional river/stream/canal lines, parks/grass, buildings, airport infrastructure and railways. Separating query, frame and SVG code is a good foundation. The original cache and AbortController scaffolding are worth retaining conceptually, but several advertised behaviors have limitations.

The older `MAX-EXPORTER-ANALYSIS.md` overstates multipolygon correctness and cancellation responsiveness: role ordering plus `fill-rule="evenodd"` is not ring assembly, and polling an abort flag inside a blocking main-thread loop does not let a click handler run.

## Integration delivered

The app has two feature tabs: **Terrain STL** and **Laser map SVG**. They share the map, search, selected geographic rectangle and handle controls. Terrain keeps its existing width/relief/stock/tiling/data-source settings. Laser settings are independent and persisted in `mapscontour-laser-settings` browser localStorage.

Laser workflow: **Area → Layers → Export**. `src/laser/LaserPanel.tsx` provides physical dimensions, layer styles and operation controls; `useLaserExport.ts` handles cancellation/progress, cached fetched features, immutable export snapshots and stale-result feedback. `shared/laser-query.mjs` preserves the original layer selectors and validates requests. `server/laser.mjs` requests the public Overpass endpoint and saves `map.svg` plus `settings-credits.json` in `data/laser/<id>/`. `src/laser/worker.ts` runs `geometry.ts` outside the UI thread. Polygon clipping uses the MIT-licensed `polygon-clipping` library; lines use actual segment clipping. A synthetic demonstration can exercise generation without a public map-data request.

The app still binds to 127.0.0.1. It does not embed the old page in an iframe or load its duplicate CDN/Bootstrap/MapLibre stack. Neither feature silently selects the other feature's online data source. Laser generation explicitly sends the chosen bounds/layer query to `overpass-api.de`; the basemap and place-search switch is independent.

## Recommended next features, in order

1. **Connected cutout mode.** Buffer road/rail centerlines to user-defined physical widths, union intersections, detect detached islands, and offer bridges/tabs or a backing-layer design. Today, this is a layered vector exporter: its cut operations are not a guarantee that a complete road-map sheet will remain connected. Acceptance: an island/bridge overlay and a count of all disconnected components before export.
2. **Manufacturing preflight.** Minimum wall/bridge width, smallest feature/island area, tiny segment removal, self-intersection checks and exact partial-overlap deduplication. Work in physical millimetres with user-specified tolerance. Acceptance: every removal/change is counted and visible in preview rather than silently discarded.
3. **Kerf and machine profiles.** Measured kerf compensation with inside/outside contour direction, calibrated widths, saved material/operation presets and bed dimensions. Do not infer speed/power or a laser-specific kerf. Acceptance: test coupons and a documented reference measurement; verify contour offsets around holes as well as outlines.
4. **Layer-specific files and tiling.** Separate SVGs for cut/score/engrave or construction layers, registration marks, chosen sheet size and explicit cut-boundary handling. DXF can follow after verifying physical scale and closed contour semantics across actual target laser editors.
5. **Stronger geographic correctness.** Use a common local projected CRS between terrain and laser when exact alignment is needed; currently laser uses uniformly scaled Web Mercator and approximate local ground scale. Consider an explicit export alignment contract for laser overlays on terrain tiles. Support wrapped antimeridian areas only with real geometry splitting, not bounds normalization alone.
6. **Better OSM completeness and classification.** Road link classes (`*_link`), footways/cycleways, bridges/tunnels as separate styles, light rail/trams, water/coastline assembly and local OSM extract import. Overpass bbox selection and incomplete OSM mapping do not guarantee every intersecting feature is retrieved; report this instead of presenting empty results as authoritative absence.
7. **Measured estimates and service controls.** Cached count/vertex-based estimates, cache size/TTL management, endpoint status and a deliberate user-configured endpoint or local OSM source for heavier use. Avoid automatic requests per drag, automatic bulk subdivision or spraying retries across public mirrors.
8. **Browser and editor interoperability fixtures.** Exercise tab switching, cancel during geometry build, stale downloads, mm/in imports, hole rendering and cut/engrave styles in the actual laser editor used in the workshop. Automated unit/API coverage does not replace a physical import/calibration test.

## Data-service references

- [Nominatim policy](https://operations.osmfoundation.org/policies/nominatim/): explicit searches, maximum one request per second, no autocomplete.
- [Overpass public-instance guidance](https://dev.overpass-api.de/overpass-doc/en/preface/commons.html): shared capacity; local/manual use should remain modest; heavy use needs an extract or dedicated service.
- [OSM copyright/ODbL and attribution guidance](https://www.openstreetmap.org/copyright): retain source/license metadata and provide appropriate visible attribution when distributing the resulting maps. Metadata alone does not necessarily satisfy visible-attribution requirements.
